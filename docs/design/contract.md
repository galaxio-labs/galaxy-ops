# 对外契约（external contract）

- 状态：方案（待评审）
- 最后更新：2026-10-11
- 关联：`docs/design/prj-backup-restore.md`（现场态 / 备份）、issue #27（备份分档命名）、issue #28（“可重建”判据）

## 1. 背景

`prj backup` 的选取（`backup`）与 `sys-prj.yml: protect`（旧名 `preserve`），都以“现场态”为单位，且**按路径**管理。但真实部署里有一类东西**用路径装不下**：

- 它是**现场决定**的（从交付包推不出）；
- 一旦丢失，**连人工都无法再次还原**（它编码的是系统之外的**外部事实**）；
- 它是**对外公开**的（域名、对外端点、公开证书）。

issue #28 的反例 `configs/gateway/wist-gateway.toml` 正是它：**看起来**是渲染物（可重建），却烘着一个现场选择 `public_base_url`（客户域名）。两条轴在同一个文件上对立，只能互相妥协。

## 2. 定义

> **对外契约 = 不可重建的公开现场事实。**

它是系统与外部世界的**契约**：对外域名、对外端点 / 端口、公开证书 / SAN。

两个**判定属性**，各自推出行为：

| 属性 | 后果 |
| --- | --- |
| **不可重建**（连人工也补不回） | 必须保护：升级**不覆盖** + 必进**备份** |
| **公开**（非私密） | 可**独立、公开**地版本化与 review（无需离机保管）；但也必须**防止它被当成“可重建物”埋进交付包** |

### 2.1 定位：可重建 × 公开 / 私密

|  | **公开** | **私密** |
| --- | --- | --- |
| **不可重建** | **对外契约**（本文）：必须留，**可公开管理** | 身份 / 凭据（`SEC_*`）：必须留，**离机保管** |
| **可重建** | 交付物 / 渲染产物：随包走、升级覆盖 | 本地可再生成的运行态：可丢 |

与私密**对偶**：私密是“不可重建 × 私密”（`~/.galaxy/sec_value.yml` / `SEC_*`，运行时注入、不进包）；对外契约是“不可重建 × **公开**”。

## 3. 判定属性 = issue #28 要的“可重建判据”

issue #28 问：能否把“可重建”写成一条可判定规则。答案是换成更硬的一条：

> **不可重建 ⟺ 丢失之后，没有任何路径（版本、现场重生成、人工重建）能再得到它。**

对外契约是它的**反面典型**。工具无法自动判定该属性（它依赖系统之外的现实），但可以判定**由它推出的集合关系**（见 §6）。

## 4. 声明（`sys-prj.yml`）

与 `ignore` / `protect` / `backup` **同构**：`contract:` **只列文件或目录**（glob，相对系统根）；
**具体的契约信息放在这些被列出的文件里**，不写进 `sys-prj.yml`。

```yaml
# sys-prj.yml
contract:
  - configs/gateway/public          # 目录：契约事实（域名 / 端点 / 证书）就在里面
  # 或单个文件：
  - configs/gateway/public.yml
```

## 5. 落点（声明 vs 内容）

- **声明**：`sys-prj.yml: contract: [...]` —— 只指路，由**系统作者**写、**在包内**（每部署一致）。
- **内容**：被列出的文件 / 目录 —— 现场选的、不可重建的事实，**site-owned、不在包内**。
- 即：`contract:` 声明随包走；契约**内容**不是安装包的文件（`prj sync` 只覆盖包内文件，天然不动它）。

## 6. 行为

`contract:` 的语义**自足**——声明即得三件事，使用者**不需要知道它和 `ignore` / `protect` / `backup` 是什么关系**：

> 命中 `contract:` 的路径 ⇒ **不覆盖（protect）+ 必收（backup）+ 不进包**。

用户侧两个命令（与既有 `sys package` / `prj import` 同词汇）：

| 命令 | 做什么 |
| --- | --- |
| `gops prj contract export` | 把本部署的契约事实打包成**归档**（日期时间命名，如 `<系统>-contract-YYYYMMDD-HHMMSS.tar.gz`），用于交付 / 迁移 / 存档 |
| `gops prj contract import` | 从归档把契约灌回本部署：写进 `contract:` 列出的文件，并投影到消费面（渲染模板 / `.env` / 证书）。**幂等**（同一归档重复导入结果不变） |

归档的**落点 / 份数**由**项目侧** `ops-prj.yml: contract` 决定（对称于 `backup:`；缺省 = 项目根、保留 10 份）：

```yaml
# ops-prj.yml
contract:
  target: ./contract   # 归档落点（可写 `${VAR}`；缺省 = 项目根）
  keep: 3              # 保留最近 N 份
```

> `contract` 声明（哪些路径是契约）在**系统侧** `sys-prj.yml`；`contract` 归档的落点 / 份数在**项目侧** `ops-prj.yml`。两者同名不同层。

**不定义** `contract` 与 `ignore` / `protect` / `backup` 的优先级或包含关系——即不把这几组声明
当成一个需要推理的系统。取而代之的**唯一约束是“不交叠”**：一个路径（含其任意祖先）只写在**一处**。
交叠不是用优先级去解决，而是**声明错误**，由 `diagnose` 报出。

`diagnose` 只查契约**自身**的问题：

1. 齐备 / 一致；
2. 契约事实被埋进可重建交付物（issue #28 反例 1）；
3. 与其它声明交叠。

## 7. 契约在各轴的落点（不是跨声明的“关系”）

- **打包**（`ignore` / 交付）：契约**内容**不进包；**投影产物**在包内。
- **覆盖**：契约**内容**不覆盖、不删。
- **备份**：契约**内容**必收（人工也补不回）。
- **私密**（`SEC_*`）：对偶面（不可重建 × 私密）。

## 8. 与 issue #28 的关系

拆出 `contract` 后，`public_base_url` 从渲染物里挪到独立事实：

- 渲染物退回**纯交付物**（可重建、随版本更新）；
- 契约事实成为“不可重建的现场态”，与 `protect` / `backup` 两条行为**自动一致**——不再需要在同一个文件上互相让步。

即：**把“现场选择”从渲染物里拆出去，落到一个本来就不可重建、且独立的契约声明上。**
